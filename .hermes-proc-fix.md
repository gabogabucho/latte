# OpenCode process-group caller coverage evidence

## Scope

- Added an injectable `spawnImpl` seam to `OpenCodeServer` and routed it through `spawnInOwnProcessGroup`.
- Added caller-level coverage for Linux (`detached: true`) and Windows (`detached` unset) in `tests/backend/opencode-kill.test.ts`.
- The fake spawn throws immediately after capturing options, so startup is bounded and no provider is launched.

## RED / mutation proof

1. Before wiring `OpenCodeServer` to the injected spawn, the focused test failed twice because the real missing executable was used instead of the injected fake (`expected /spawn captured/`, received `ENOENT`).
2. Temporarily bypassing `spawnInOwnProcessGroup` made the Linux case fail: expected `detached: true`, received `undefined`.
3. Temporarily passing the wrong platform (`win32`) to the helper produced the same Linux failure.
4. Both mutations were restored before final verification.
